## Question

Can HTTP writes avoid invoking a native-installed SIGPIPE handler while retaining BrokenPipeError and cancellation cleanup?

## Setup

Importing rebel changes Linux SIGPIPE from ignored to caught (observed through /proc/self/status), even though Python signal.getsignal still reports SIG_IGN. A closed socketpair write after import emits a native backtrace. The HTTP matrix originally produces6 native backtrace headers per run. No process-global signal handler change is needed: use socket.sendall(data, MSG_NOSIGNAL) for the unbuffered HTTP writer. Platforms without the flag retain flags0; no protection is claimed there.

Hardware harness from #211 uses production serve_batched.build, one B1 lane, context9216 and3 KV blocks. Synthetic token fixtures128/2048/8192, output32, ignore_eos, concurrency4/8 queued on one lane. Module loaders select the candidate batcher and llmd before importing batched; installed SDK remains unchanged.

## Conclusion

The observed SDK signal-handler interaction is avoided per HTTP write on Linux without suppressing Python exceptions or changing process-global handlers. This is a disconnect robustness fix, not a throughput or numerical-accuracy optimization. Broader four-model RNGD/heterogeneous coverage remains open.
