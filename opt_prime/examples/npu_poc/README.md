# npu_poc — Pipeline (PP) + Tensor (TP) Parallel Inference on Korean NPUs with opt_prime

A proof of concept that runs LLM inference on a **PP × TP grid** of NPUs by
feeding opt_prime's **IR capture + PP split** directly into the vendor compiler,
**without modifying a single line of the opt_prime engine**.

| Backend | Status |
|---|---|
| **Rebellions ATOM+** (RBLN-CA22, `rebel-compiler`) | Working — all examples below |
| **FuriosaAI RNGD** (`furiosa-torch`) | Working — one-shot inference and generation with PP (see [RNGD](#6-furiosaai-rngd)) |

## Overview

### Parallelism ownership

```
PP  owned by opt_prime   IR capture (torch.export) → split → stage wiring (top-level FX forward)
TP  owned by the backend ATOM+: rebel bakes the collectives into the compiled binary
                         RNGD: PE fusion — the cores of one device run a stage together
```

Each stage of the split `GraphModule` (`submod_k`) is **replaced** by an NPU wrapper
compiled by the backend; the top-level FX forward generated by opt_prime then
becomes the pipeline as-is.  Tensors crossing stage boundaries go through host
memory.  The number of cards used is PP stages × TP size (length of
`--device-ids` = PP × TP).

### One-shot inference (a single prefill)

The prompt is passed through once to obtain logits; no KV cache is used.  The
reference is the same module run on the CPU with the same input, without
compilation, and the NPU output is compared against it.  Equivalence is judged in
three tiers, checked in order — ① `allclose` ② `|Δ|max` relative to the value range
+ cosine ≥ 0.999 ③ argmax agreement — and the first tier that holds is the verdict
(`PASS(strict)` · `PASS(relaxed)` · `PASS(argmax)`); if none holds the run fails.
Element-wise `allclose` alone is not usable because NPU arithmetic is not
bit-identical to fp32 on the CPU.

### Continuous inference (generation — one prefill + N decode steps)

After the prefill, tokens are produced one at a time.  Every decode step needs the
K/V of all previous tokens, so **where the KV cache lives** is the central design
choice.  The reference is CPU greedy decoding of the same model and prompt.
Results are reported in two ways: **teacher forcing** (the CPU's correct token is fed
at every step, measuring per-step numerical accuracy) and **free-running generation**
(the model's own output is fed back — small errors can be amplified).
The verdict uses teacher forcing.  A step whose token differs from the CPU is counted
as a **tie** rather than a miss only when, at that step, the two tokens' logits are
within the measured error of each other on **both** the CPU and the NPU, and the
logits' cosine is ≥ 0.999.  The error is the NPU↔CPU `max|Δ|` over all other tokens
(the two disputed tokens are excluded, so a wrong logit cannot widen its own margin).  Two candidates that close cannot be ordered at bf16
resolution (~0.06 near typical logit values), so `argmax` decides by index.  Ties are
reported separately (e.g. `31/32 exact + 1 tie`); any miss fails the run.

### KV cache — two paths

| | **Functional cache** (default, `--generate`) | **Resident cache** (optional, `resident_generate` · `resident_pp_generate`) |
|---|---|---|
| Where the cache lives | Graph **inputs/outputs** — round-trips host ↔ NPU every step | **Resident in NPU memory** — never leaves the device |
| Model changes | None · no vendor-specific ops | None — but the SDPA in the captured graph is rewritten to a **vendor paged-attention op** |
| Binaries | Shapes change with the past length, so they are grouped into **buckets** (`--buckets`) | Decode is always `(1,1)` — no buckets needed |
| Parallel axes | **PP × TP** (TP>1 needs rebel-compiler 0.12 or later) | **PP × TP** |
| Constraints | — | Prompt length ≤ block size (default 128, `NPU_POC_BLOCK`).  Assumes an unpadded prefill |

The resident cache relies on vendor-specific ops, which conflicts with the goal of
avoiding vendor-specific LLM implementations, so it is **not the default**.  It
serves as a reference point showing what that goal costs (longer contexts; with
rebel-compiler 0.10.x it was also the only path with TP>1).

## Requirements

Set up the NPU software stack (driver, firmware, runtime and the vendor's Python
compiler package) following the vendor documentation —
[Rebellions](https://docs.rbln.ai) for ATOM+, [FuriosaAI](https://developer.furiosa.ai)
for RNGD — and use one virtual environment per backend, so that another installation
(e.g. in the user site-packages) is not picked up.  A compiler package that does not
match the installed driver stops while loading the runtime (for ATOM+:
`librbln-thunk.so library version is not in the supported range`).

The versions this PoC was validated with:

```
torch 2.13.0 (CPU build) · transformers 4.46.2 · rebel-compiler 0.12.0 · Python 3.10
RBLN-CA22 cards with ATOM+ driver/firmware 3.4.1 — 1 to 4 depending on the example
meta-llama/Llama-3.2-1B — a gated model; log in to Hugging Face first (`huggingface-cli login`)
```

rebel-compiler loads the installed ATOM+ runtime library, so its version must match
the driver (rebel-compiler 0.12.0 ↔ driver 3.4.1).  Install it from the Rebellions
package index (`pip install rebel-compiler==0.12.0 --extra-index-url
https://pypi.rbln.ai/simple`, login required).  Earlier pairs (rebel-compiler 0.10.3
↔ driver 3.0.0, torch 2.8) were also validated, except TP>1 with the functional KV
cache.

RNGD (example 6) uses its own environment — the furiosa SDK pins torch, so the two
backends cannot share one:

```
torch 2.10.0 · transformers 5.19.0 · furiosa-torch 2026.4.0 · Python 3.10
RNGD cards — 1 to 3 depending on the example
```

Only `furiosa-torch` (and the `furiosa-kernels` it depends on) is needed; the
higher-level `furiosa-llm` packages are not used by this PoC.  The adapter is
validated with furiosa-torch 2026.4; 2026.3 and 2026.2 (with transformers 5.1.0)
also run, with generation keeping the first stage on the host (`--cpu-stages 0`).

Run every command **from `opt_prime/examples/`** — the directory that contains
`npu_poc/` — after cloning this repository:

```bash
cd opt_prime/examples        # relative to the repository root
```

The entry points put `opt_prime/` (the parent of the engine package) on the
path, so no installation is needed.  A successful run ends with a
`[poc] RESULT PASS …` line.

## Examples

### 1. One-shot inference — PP

```bash
# Synthetic model (a stack of nn.Linear), 2 cards — environment check
python3 -m npu_poc.poc --model synthetic --pp 2 --device-ids 0,1

# Llama-3.2-1B in 2 stages — 2 cards
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --device-ids 0,1

# 4 stages — 4 cards
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 4 --device-ids 0,1,2,3
```

### 2. One-shot inference — TP and PP × TP

```bash
# TP=2 (one stage sharded across 2 cards)
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 1 --tp 2 --device-ids 0,1

# PP=2 × TP=2 — 4 cards
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --tp 2 --device-ids 0,1,2,3
```

### 3. Throughput — micro-batch pipelining

```bash
# Overlap 8 requests through the pipeline and compare against serial execution (same binaries)
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --device-ids 0,1 --microbatches 8
```

### 4. Continuous inference — functional KV cache

```bash
# Generate 32 tokens with PP=2 (past-length bucket 64)
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --device-ids 0,1 \
    --generate 32 --buckets 64 --dtype bfloat16

# PP=2 × TP=2 — 4 cards (rebel-compiler 0.12 or later)
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --tp 2 --device-ids 0,1,2,3 \
    --generate 32 --buckets 64 --dtype bfloat16
```

### 5. Continuous inference — resident KV cache (optional · vendor paged-attention op)

```bash
# (a) Check only the graph rewrite against the original on the CPU — no NPU used
python3 -m npu_poc.poc --model meta-llama/Llama-3.2-1B --input text --pp 2 --device-ids 0,1 --resident-cache

# (b) Generate 32 tokens with the resident cache × TP=2 — 2 cards
TP=2 NEW=32 SEQ=16 python3 -m npu_poc.resident_generate

# (c) PP=2 × TP=2 × generation — 4 cards
PP=2 TP=2 NEW=16 SEQ=16 python3 -m npu_poc.resident_pp_generate
```

`resident_generate` and `resident_pp_generate` are configured through environment
variables — `TP` · `PP` · `NEW` (number of tokens to generate) · `SEQ` (prompt
length, ≤ block size).

### 6. FuriosaAI RNGD

Run with the RNGD environment above.

```bash
# Llama-3.2-1B in 4 stages — all 4 stages on the NPU (4 devices on 3 cards)
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 4 --device-ids 0,1,2,4

# Generate 8 tokens — prefill and decode, all 4 stages on the NPU
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 4 --device-ids 0,1,2,4 --generate 8

# GPT-2 in 2 stages — 2 cards
python3 -m npu_poc.poc --backend rngd --model gpt2 --pp 2 --device-ids 0,2

# Overlap 8 requests through 4 stages and compare against serial execution
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 4 --device-ids 0,1,2,4 --microbatches 8

# PP=3 × TP=2 — each stage on one whole card (two base devices fused)
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 3 --tp 2 --device-ids 0,1,2,3,4,5

# TP=4 — the first stage on two cards; the stage holding lm_head on the CPU
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 2 --tp 4 --device-ids 0,1,2,3 --cpu-stages 1

# Generate 32 tokens with the in-place KV cache — caches stay on the stage devices
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 4 --device-ids 0,1,2,4 --generate 32 --inplace-cache
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.2-1B \
    --pp 3 --tp 2 --device-ids 0,1,2,3,4,5 --generate 128 --inplace-cache

# Llama-3.1-8B — one-shot in 4 stages; generation needs smaller stages (6 here)
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.1-8B \
    --pp 4 --device-ids 0,1,2,4
python3 -m npu_poc.poc --backend rngd --model meta-llama/Llama-3.1-8B \
    --pp 6 --device-ids 0,1,2,3,4,5 --generate 32 --inplace-cache
```

Notes on the RNGD adapter (`backends/rngd.py`):

- **Devices.**  `NPU_POC_RNGD_FUSION` sets how many cores form one base device
  (default 4, i.e. two devices per card).  `--device-ids` indexes base devices,
  so `0,2,4` places one stage on each of three cards.  The fusion setting applies
  to the whole process.
- **TP.**  On RNGD, TP is the number of cores fused into one device: `--tp k`
  fuses k base devices into one (`--tp 2` = one whole card).  Each stage takes
  k consecutive base devices starting at a multiple of k (`0,1` · `2,3` …).
- **Larger devices (`--tp 2`, one card per device).**  When a device spans 8 or
  more cores, the compiler limit on unique shapes for tactic generation is set to 4
  (`NPU_POC_RNGD_MAX_UNIQUE_SHAPES`: `auto` (default) · `<n>` · `default` for the SDK's
  own setting).
- **Two cards per device (`--tp 4`).**  The compiler uses its default tactic hint
  with estimate-ordered tactic search there (applied automatically unless
  `NPU_POC_RNGD_TACTIC_HINT` is set).  A stage holding `lm_head` did not compile
  across two cards in our tests — place it with `--cpu-stages`.
- **dtype.**  Runs in bfloat16; another `--dtype` is ignored with a warning.
- **Compiler setting.**  Each stage is compiled with the compiler's LLM tactic
  hint — the prefill hint for multi-token stages, the decode hint for
  single-token stages (`NPU_POC_RNGD_TACTIC_HINT`, default `auto`; `default`
  leaves the SDK's own setting).
- **Model patches** (applied automatically, values unchanged): causal-mask
  construction is skipped for unpadded prefill, other masks are built as float
  additive masks in the model dtype (the decode-step mask from integer positions
  and arithmetic, without boolean gather or AND), RoPE cos/sin are expanded to
  the batch size, and `nn.LayerNorm` is written out explicitly.
- **Micro-batch pipelining** (`--microbatches`) uses stream submission and
  needs furiosa-torch 2026.3 or later (rejected before compiling on older
  versions).  A call on a device returns at once and queues behind earlier calls
  on that device, so inputs are copied without waiting and each result is read
  after an event recorded right behind its own call, on a separate copy stream.
- **In-place KV cache** (`--inplace-cache`, with `--generate`; Llama-family
  models, batch 1).  Each stage's K·V caches are allocated once on that stage's
  device and updated in place (`index_copy_`), so a decode step moves only the
  token, its position, a 2-D mask, RoPE cos/sin, stage-boundary hidden states and
  the logits.  The graphs are the ones opt_prime captures, rewritten before the
  split and split with `llama-tp-split`; only standard PyTorch ops are used
  (`inplace_cache.py`).  The cache capacity is the smallest `--buckets` entry
  that holds prompt + N.  Validated layouts (Llama-3.2-1B, SDK 2026.4): PP=4 · PP=3 × TP=2 ·
  PP=2 × TP=4 with `--cpu-stages 1`, capacity up to 1024; `--pp 1` is rejected
  (a single 16-layer stage did not compile).
- **Layers per stage (Llama-3.1-8B, 4-core devices).**  One-shot inference
  compiles with 8–9 layers per stage (PP=4 · PP=3 × TP=2 · PP=2 × TP=4).
  Stages that carry a KV cache compile with fewer layers: the in-place cache
  with up to 7 layers per stage (PP=5 and PP=6; 9 layers did not compile), the
  functional cache at PP=6 (PP=5 did not compile its first decode stage).  With
  2-core devices (PP=8) the prefill and decode programs of a stage did not fit
  in device memory.
- `NPU_POC_RNGD_CACHE=<dir>` keeps compiled stages across runs; a first compile
  takes a few minutes per stage.

## Main options

| Option | Meaning |
|---|---|
| `--backend` | `rbln` (default) · `rngd` |
| `--pp` · `--tp` · `--device-ids` | Grid and cards.  Length of `--device-ids` = PP × TP (NPU stages only) |
| `--cpu-stages` | Stage indices kept on the host (e.g. `0`) — not compiled; the other stages run on the NPU |
| `--partitioner` | How to cut the pipeline.  `balanced` is this PoC's compute-balanced split |
| `--input` | `text` tokenizes real sentences (default for HF models) · `random` uses random tokens (default for `--model synthetic`, which has no tokenizer) |
| `--dtype` | Compute dtype (`float32` · `bfloat16`) |
| `--attn` | `attn_implementation` (`sdpa` by default · `eager`) |
| `--seed` | Input seed (default 0) — without a fixed seed the equivalence metrics vary from run to run |

Run `python3 -m npu_poc.poc --help` for the full list.
