## Question

Do real GPU-prefill/GPU-decode HTTP requests work for all four models across128/2048/8192tokens, queued concurrency4/8 and lifecycle events? Are concurrent outputs identical to each configuration's serial baseline?

## Setup

Existing HTTP validator now forwards decode and prefill device selection to serve_batched.build and requires actual remote prefill/transfer counters. Decode uses GPU1 with4slots, context9216, page64, local chunk256; optional producer uses GPU0 and existing TorchPrefillEngine defaults (chunk2048 and producer prefix cache enabled). Decoder prefix cache is initially disabled. Output length32 ignoring EOS; stream cancellation uses256tokens. This is a lifecycle/numerical matrix, not a semantic quality or matched speedup experiment. Producer cache policy differs from decoder cache policy and is reported explicitly.

Each process initializes its own model(s). Existing SIGPIPE-safe HTTP9e442cd is injected by a local runner before loading validate.py. Other workloads are not touched. GPU standalone and PD use the same patched HTTP module.
