# Four-model native GPU cache condition grid

- Date: 2026-10-30; related #212/#201 and PR279.
- Runtime: `8f9f2a05178bcbb859c97dce2e5ee1bbc23eca3e` (PR266 experiment branch), not current main.
- Hardware: one A100 80GB PCIe; driver 580.178.04. PyTorch 2.13.0+cu130, Transformers 5.15.0.

## Setup and correctness

Four selected models, each in fresh cache-off then cache-on server processes. Both use BF16, four decode slots, context 9216, page size 256 and chunk 256. Prompts have 128/512/2048/8192 tokens; outputs have 32/128 tokens; client concurrency is 1/4/16. Requests are greedy and ignore EOS. Each cell has one timed SSE batch after warmups and full-token checks. Repeated token-ID prompts are generated by the included fixture.

All eight arms finished with exit 0: 192 conditions and 2,752 responses (64 warmups, 1,344 token checks, 1,344 SSE checks). Every cache-on response matches its fresh same-model, same-page-size cache-off reference. Full token arrays are checked for nonstream responses; exact rendered text and output length are checked for SSE responses. No semantic answer-quality claim follows from this fixture. Cache-hit counters are zero in every disabled arm and positive in every enabled arm.

The independent auditor checks actual responses, exact condition/warmup sets, resource metadata, configuration/reference hashes and timing arithmetic. Twelve selfchecks include corrupted responses, duplicate warmups, duplicate/incomplete arms, wrong references/resources and incorrect throughput. Both the original child processes and coordinator exit 0; a fresh GPU compute query is empty before the next experiment starts.

The initial attempt failed configuration validation because of an unsupported `page_size` metadata key, before a server was started. Removing that metadata key while retaining `--page-size 256` in server argv resolved the setup error. Initial queue/log/configs are retained separately as `cachefull212-*`; measured retry files use `cachefull212r1-*`.

## Reproduction

Use the recorded runtime and environments. `full_grid_http.py` is the measured fixture with only two publication guards: an explicit server config is required, and existing output paths are rejected before model import. `http267_diagnostics.py` is copied unchanged. Configure interpreter, runtime checkout and frozen model paths in the example JSON. For cache-on, add `--prefix-cache` to server argv and set `metadata.decoder_cache` to true. Keep page size 256 in both arms.

```bash
export PYTHONPATH="$RUNTIME/opt_prime:$RUNTIME/opt_prime/examples/pd"
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 "$PYTHON" full_grid_http.py   --model "$FROZEN_MODEL" --mode native --server-config "$OFF_CONFIG"   --lengths 128 512 2048 8192 --outputs 32 128 --concurrency 1 4 16   --repeats 1 --request-timeout 180 --output "$NEW_OFF_RESULT"
# Repeat with ON_CONFIG, a new output path and --reference "$NEW_OFF_RESULT".
python audit_full_grid.py "$ARCHIVED_ARTIFACT_DIRECTORY"
python selfcheck_full_grid.py "$ARCHIVED_ARTIFACT_DIRECTORY"
```

The archived directory contains `cachefull212r1-gpu-queue.json`, eight `cachefull212r1-{model}-{off,on}-config.json` files and corresponding raw JSON results. Model aliases are qwen06b/qwen4b/gemma/koni. The coordinator checked for idle GPU compute processes before every arm; preserve exclusive access when reproducing timings. Site-local paths and full raw responses are not published.

## Limits

This expands the page256/chunk256 mitigation evidence; it does not fix the original page64 history failures or change defaults. Prefixes are repeated, not a diverse workload. It does not establish NPU/heterogeneous cache behavior, host-capacity eviction, multi-slot reload faults, semantic quality or current-main support. The previous device-eviction and host-reload controls remain separate evidence. #212 and #201 remain open.
