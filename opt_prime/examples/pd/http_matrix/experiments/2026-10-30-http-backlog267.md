# Preserve HTTP connection bursts while accept is delayed (#267)

The common serving listener inherited Python3.10 ThreadingHTTPServer's backlog5. Sixteen clients connecting during a brief accept pause can exhaust it. A real-socket regression holds the accept thread before it starts: the original listener times out; the candidate accepts all16 connections. The candidate sets backlog128 before bind/listen without changing engine admission,request timeouts or request processing.

## Limits

No before/after throughput gain is claimed because the original did not finish timed measurements. ATOM Qwen4 also reset underc16 on the original listener with no OOM;its candidate retry and remaining GPU model/routes are pending. Engine concurrency,KV-cache correctness and resource limits are unchanged. Related#267 and#201;not closing either issue.
