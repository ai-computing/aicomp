## Question

Can a real pending RNGD prefill be cancelled without corrupting the next ATOM request? Does terminating its owned worker fail queued requests promptly and allow explicit healthy replacement?

## Setup

Four models, width2048, four medium semantic cases1526–1643tokens. Qwen3-0.6B runs first, followed by Qwen3-4B,Gemma3-1B,KONI8B with their validated underlying factories; KONI usesk1, Gemma corrected artifactroot. Reuse the existing artifact and input/native-output fixtures. Test-only observer_factory marks native prefill entry and completion atomically; it does not delay execution, gate results or replay saved KV. Fault injection requires both an entry marker and an unfinished request Future. The instrumented parent imports the already CPU-tested SubprocessPrefillWorker candidate process-locally; shared SDK installations are unchanged.

The standard14output checks and16remote requests run first. Then cancel during native prefill, verify reuse, terminate only this harness's worker while a second HTTP request is queued, assert both fail and a later request fails, close/unlink the dead slab, explicitly construct a replacement worker at an idle boundary and verify native-output equality. This is not automatic service restart or replay. No device-wide reset or other workload is touched.
