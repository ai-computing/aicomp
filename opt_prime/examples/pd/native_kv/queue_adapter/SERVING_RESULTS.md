# Serving result: isolated KV improvement did not improve mixed HTTP serving

The tested adapter reduced reverse-contiguous KV handoff latency, but did not improve the measured HTTP serving workload. Keep it opt-in and experimental.

## Reproduction and setup

Base commit: `7f4f4a9d7b0b2e43d1f31c516dfab8117ed84a01`, plus adapter sources identified by `measured_manifest.json`. RNGD device 0, SDK/driver 2026.4.0; GPU decoder on an A100 80GB PCIe. Qwen3-8B-FP8 model revision `220b46e3b2180893580a4454f21f22d3ebb187d3`, FXB SHA256 `36d74b754f580bea893c68cc70147c615d1a9c4273a4580dbebaf87287400713`.

Build with the README commands. Run the baseline native CLI and the adapter bootstrap with identical native arguments:

```text
serve MODEL --served-model-name Qwen/Qwen3-8B-FP8 --fxb FXB --devices npu:0 --host 127.0.0.1 --port 19101 --no-enable-prefix-caching --experimental-kv-transfer-config '{"kv_connector":"TcpConnector","host":"127.0.0.1","port":19201,"poll_timeout_ms":1}'
```

GPU server and HTTP benchmark, from the parent native_kv directory:

```bash
python3 serve_gpu.py --model-dir MODEL --pipeline --batch-size 16 --native-batch-size 8 --norm-mode fused --fuse-mlp --fuse-qkv --native-pack direct --rolling-native --stream-native-kv
python3 bench_arrival_http.py --rates 6,12 --requests 96 --out result.json
```

Restart both servers for each run in baseline/adapter/adapter/baseline order. No debugger or native profiler attached. Inputs are deterministically generated by bench_arrival_http.py: lengths 128/512/1024, outputs 32/128. Native standalone is a separate control; heterogeneous serving uses an additional GPU, so these results are not cost parity.

## Results

KV-only handoff is `kv_ready_ms - ready_ms`, including D2H, transport and receiver assembly. Repeated token ID 1000; discard the first two repetitions per geometry per process. Each complete KV buffer is hashed against baseline. Two runs per mode, 272 total request exports, all hashes match.

| Input tokens / concurrency | Baseline mean ms | Adapter mean ms | Baseline p95 ms | Adapter p95 ms |
|---|---:|---:|---:|---:|
| 128 / 1 | 13.25 | 7.53 | 21.04 | 8.22 |
| 512 / 1 | 39.32 | 20.26 | 66.11 | 21.84 |
| 1024 / 1 | 78.50 | 40.05 | 128.21 | 44.51 |
| 1024 / 4 | 88.11 | 38.21 | 143.81 | 41.95 |

HTTP ranges below are the two observed run results, not confidence intervals. All 1536 HTTP benchmark requests succeeded (768 heterogeneous and 768 native standalone).

| RNGD prefill -> GPU decode | Baseline TTFT p95 ms | Adapter TTFT p95 ms | Baseline output tok/s | Adapter output tok/s |
|---|---:|---:|---:|---:|
| 6 requests/s | 238.7–239.5 | 245.1–247.8 | 438.6–438.9 | 438.9–439.3 |
| 12 requests/s | 235.5–236.3 | 247.0–265.2 | 796.7–797.7 | 796.7–798.0 |

The adapter restored all 5040 rewritten transfers across the two measured processes, with zero failed completions, zero remaining in-flight metadata and zero capacity/duplicate fallback. These counters combine KV-only and HTTP phases; they alone do not show coverage of HTTP transfers. A separate phase-counter diagnostic is recorded below when complete.

Unit tests pass with AddressSanitizer/UndefinedBehaviorSanitizer. Hardware smoke matched 4/4 full KV hashes before the timed runs. This is an experimental binary-specific adapter; production cancellation, lifetime and broader workload coverage remain separate requirements.

## Coverage and correctness diagnostic

A separate counter-instrumented run repeated KV-only export then 24 mixed HTTP requests per endpoint (plus benchmark warmups). In the HTTP phase there were 2197 pageable read commands: 469 single-segment and 1728 multi-segment. Only 72 multi-segment commands were eligible for this full reverse-contiguous rewrite (4.17%). All 72 restored successfully. Most mixed-serving scatter layouts therefore do not meet this adapter's geometry condition. This explains the limited applicability; it does not establish that the measured TTFT regression is caused solely by hook overhead. Diagnostic timings are excluded from ABBA figures.

Quality: 15/15 cases produced identical text across native, GPU and streamed GPU responses. Strict-format grading passed 12/15 on each endpoint, not 15/15. Sixteen closed HTTP streams were followed by 16 successful, identical recovery responses. No transformed commands were added during the quality/recovery phase, so this is not a test of cancellation while a transformed DMA is active.

Conclusion: isolated handoff improved, HTTP throughput stayed effectively unchanged, and observed HTTP TTFT p95 regressed. Do not enable this adapter by default. Next inspect and coalesce partial contiguous runs in the actual mixed-serving layouts; retain these measurements as the baseline.
