Local/remote checkpoint safetensors SHA256 both3d4ef8d71c14db7e448a09ebe891cfb6bf32c57a9b44499ae0d1c098e48516b6. Root cause isolated with a small matrix product: compile sample made by zeros_like(transposed_weight) has stride[1,128], runtime contiguous weight stride[64,1]. RelativeRMS137.25%. Replacing the sample with contiguous zeros matching runtime yields relativeRMS0. The synthetic initial layer used contiguous random weights, so it did not exercise the real-checkpoint packing boundary.

Fix: build compiler samples with explicit shape/dtype contiguous zeros, matching device parameter packing. The in-flight2K compile was deliberately terminated (exit143) before inference after the128 correctness failure; no2K result claimed. Corrected128 run succeeds with3 finite/bit-exact repeats, warm44.825/45.076ms; first token9079. GPU BF16 native/imported32-token outputs match,52slots read back exactly. RelativeRMS K0.8257%, V0.8247%, logits0.9227%. Same source/weights and input fixture; only compiler sample strides changed.

Added a consumer-retention check for long Gemma inputs: local DynamicSlidingWindowLayer retains W-1 positions while full layers retain all input positions. Compare producer tails to local retention and verify absolute cache length before decode. CPU test uses12positions/window4, verifies local3/global12 and rejects wrong absolute lengths.
