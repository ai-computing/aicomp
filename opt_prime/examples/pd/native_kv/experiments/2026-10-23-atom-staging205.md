# ATOM KV staging: arithmetic encoding and preserved strides

- **Date**: 2026-10-23
- **Task**: aicomp #205 (related matrix #201)
- **Host / device**: RNGD+ATOM host, one allocated ATOM; CPU staging with 4 OpenMP threads; rebel-compiler 0.11.0, optimum-rbln 0.11.0.post1, torch 2.11.0+cpu
- **Commit**: baseline feb40bd445 (PR195); candidate bf4f59f065902376b325eb5af303e7a6e08e4c1b plus this PR's atom_stream_upload.py patch (uncommitted at measurement)

## Question

Can the portable ATOM importer reduce CPU staging cost without changing the cache encoding or decoded logits?

## Setup

Qwen/Qwen3-4B revision 1cfa9a7208912126459214e8b04321603b3df60c, B1, context9216, three full-context KV blocks, prefix cache disabled. RNGD BF16 KV exports from the matrix fixture at 128/512/2048 tokens, 36 layers, 8 KV heads, head dimension128. Baseline is the portable importer before this patch. Candidate preserves the adapter's permuted view and encodes BF16 bits with vector arithmetic instead of a lookup table. No device kernel, wire protocol or transfer concurrency changed.

## Command

In the allocated device environment, use the same atom runtime/bootstrap as PR203. Place the three matrix exports `rngd-qwen3-4b-{128,512,2048}.pt` and compiled cache `atom-artifacts/` in the working directory. Preserve the baseline module before loading the candidate:

```bash
git show feb40bd445:opt_prime/examples/pd/native_kv/atom_stream_upload.py > atom_stream_upload_baseline.py
OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 python container_bootstrap.py bench_atom_import.py
python -m unittest discover -s . -p 'test_atom*.py'
```

`bench_atom_import.py` expects those trusted local exports and imports both modules from its search path. It saves `atom-import205.json`. Alternate baseline/candidate order on each repeat. Six repeats per length; exclude repeat0 from warm means. Timer covers import only, excluding readback and decode. Device discovery requires exactly one allocated ATOM. Artifact compilation and weights are prerequisites, not included in timing.

## Results

| Input tokens | Baseline mean ms | Candidate mean ms | Reduction |
|---:|---:|---:|---:|
|128|69.746|45.963|34.1%|
|512|212.949|133.724|37.2%|
|2048|717.191|463.479|35.4%|

Raw timings including cold first calls: `results/atom-import205.json` beside the benchmark. All432 checked device cache slots read back exactly. At each length, eight complete consecutive decode-logit vectors matched bit-for-bit between importers. Exhaustive conversion test covers all65536 BF16 bit patterns, including signed zero, saturation, NaN and infinity according to the existing cache encoding contract. Strided-input test checks input preservation and untouched cache lanes/tails.

## Conclusion

CPU staging is materially cheaper on this model and runtime. This does not establish end-to-end HTTP serving gains, overlap, DMA performance, arbitrary model support or quality parity with a separate numerical backend. Repeat under isolated host load and integrate with the serving path before claiming those outcomes. Compilation metadata for the cached target and complete environment capture remain part of the broader matrix validation.
